Lesson 8 — free hosting with GitHub Pages

What you'll learn

  • How to switch on GitHub Pages for your repository.
  • Which parts of the project can live there.
  • What GitHub Pages CANNOT do (this matters!).

Glimpse

After this lesson your lessons are online at a real public URL, like: 

https://YOUR-NAME.github.io/guestbook-site/public/index.php

(GitHub Pages serves files as-is; index.php links still open the page but PHP code inside is NOT executed — see the warning below.)

Steps

  1. Open your repository on github.com.
  2. Click Settings (top bar).
  3. In the left menu click Pages (under "Code and automation").
  4. Under "Build and deployment", set Source to Deploy from a branch.
  5. Choose branch main and folder / (root), then click Save.
  6. Wait 1–3 minutes. The Settings → Pages screen then shows a green box with your URL.
  7. Open the URL and add /public/index.php to see the lessons.

What GitHub Pages can and cannot do

GitHub Pages serves STATIC files only. It can host the HTML, CSS and JavaScript lessons — everything you built in lessons 1–3 works fine there.

PHP does not run and SQLite does not exist there. Pages has no PHP interpreter and no filesystem your code can write to. The guestbook app (lessons 4–6) will NOT work on GitHub Pages.

For the live CRUD app, continue to Lesson 11 — cPanel. Vercel (lesson 9) also serves only static files for this project.

Check it works

  1. Settings → Pages shows a green "Your site is live at…" message.
  2. The URL opens and you can click through lessons 1, 2, 3, 7, 8.
  3. Copy buttons and the lesson checkboxes still work on the live site (JS and localStorage work fine on Pages).
  4. Open /public/app/index.php on the live site: the browser DOWNLOADS the raw PHP file or shows nothing useful. That is the "no PHP here" rule made visible.
