Lesson 7 — upload the project to GitHub

What you'll learn

  • What Git and GitHub are (they are NOT the same thing).
  • Method A: uploading with the terminal (git commands).
  • Method B: uploading by dragging files on github.com.
  • Why .gitignore keeps the database out of the repo.

Glimpse

When this lesson is done, your project looks like this on github.com/your-name/guestbook-site — every file in the browser, with its history: 

guestbook-site/            (the repository root)
  public/                  index.php, lessons/, app/, assets/
  src/                     config.php
  data/                    .gitkeep only — NO guestbook.sqlite!
  .gitignore
  README.md

Git = the version-control tool that records snapshots of your files, running on YOUR computer. GitHub = a website that stores those snapshots online and lets other people see them.

Code to add / run

Method A — with the terminal

Open a terminal INSIDE your project folder (in VS Code: menu Terminal → New Terminal). Then run these commands one by one. Each line is explained below. 

git init
git add .
git commit -m "First version of the guestbook course"
git branch -M main
git remote add origin https://github.com/YOUR-NAME/guestbook-site.git
git push -u origin main
  • git init — turn this folder into a Git repository (a "repo": a project Git watches).
  • git add . — stage (select) every file for the next snapshot. The dot means "everything here".
  • git commit -m "..." — save a snapshot with a short description. Nothing is on the internet yet.
  • git branch -M main — name the current line of history "main" (GitHub's default name).
  • git remote add origin URL — connect your local repo to the empty GitHub repo you created on the website.
  • git push -u origin main — upload the snapshot to GitHub. -u remembers the link for next time; then git push alone is enough.

Method B — by dragging files (no terminal)

  1. Create an account on github.com if you do not have one.
  2. Click the + (top right) → New repository. Name it guestbook-site. Keep it Public. Do NOT tick "add a README" (you already have one). Click Create.
  3. On the new empty repo page, click the link uploading an existing file.
  4. Drag the CONTENTS of your project folder (the files inside it) into the drop area.
  5. Type a message like "First version" and click Commit changes.

Why .gitignore and .gitkeep matter

.gitignore lists files Git should NEVER save. Our file ignores data/*.sqlite: your database holds real visitor messages and must not land in a public repo. GitHub is public — anything pushed there can be read by anyone.

But Git does not track empty folders, and on some hosts the data/ folder must exist before the first run. The empty file data/.gitkeep is the usual trick: a file with no content, just so Git has something to save inside data/.

After the first run on a server, guestbook.sqlite is created by PHP and stays only on that server. Its content is yours to manage; the repo never sees it.

Check it works

  1. Open https://github.com/YOUR-NAME/guestbook-site in a browser.
  2. You see the same folder tree as on your computer.
  3. Click data/: only .gitkeep is there.
  4. Check the repo file list: no .sqlite file anywhere.
  5. (Terminal users) Run git status later — it shows which files changed and are not committed yet.
