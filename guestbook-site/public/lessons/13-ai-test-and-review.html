Lesson 13 — use AI to test and review your site

What you'll learn

  • How to ask an AI assistant to review code for security problems.
  • How to get an accessibility and responsive-design review.
  • How to read AI answers critically and verify fixes yourself.

Glimpse

The workflow is a loop. You paste code + a specific question, the AI suggests fixes, and you verify each fix in the browser before believing it. Three ready-to-paste prompts are below.

Three ready-to-paste prompts

Prompt A — security and SQL injection review

Act as a strict senior PHP reviewer. This is my guestbook handler
file. Review it ONLY for security issues:
1. SQL injection — is every query a prepared statement? Any SQL
   built from user input?
2. XSS — is every echoed value passed through htmlspecialchars()?
3. Input validation — are lengths and required fields checked on
   the SERVER, not just in HTML?
4. Anything else unsafe you notice.

For each issue: quote the line, explain the danger in one sentence,
and show the corrected code. If something is already correct, say
so explicitly.

[PASTE THE FULL FILE HERE]

Prompt B — accessibility and keyboard navigation

Act as an accessibility auditor. Review this HTML page for:
1. Keyboard navigation — can every interactive element be reached
   and operated with Tab / Enter / Space only? Is focus visible?
2. Screen reader basics — one h1 per page, logical heading order,
   every form field has a label linked with for/id, error messages
   linked with aria-describedby.
3. Contrast — list any color pairs that may fail WCAG AA.
4. Touch targets — anything smaller than 44x44 px.

Report as a numbered list: issue, why it matters, the exact fix.
If something is already accessible, say so explicitly.

[PASTE THE FULL HTML HERE]

Prompt C — responsive layout check

Act as a responsive-design tester. Here is my HTML and CSS.
Imagine testing at 320px, 768px and 1280px wide and list, for each
width:
1. What breaks or overflows (horizontal scrollbars, squeezed
   text, buttons too small to tap, tables wider than the screen).
2. Whether touch targets stay at least 44x44 px.
3. Whether images/embeds stay within max-width: 100%.
4. What you would change in the CSS, with the exact code.

Be specific: name selectors and values, do not give generic
advice.

Reading the answer critically

AI suggestions are drafts, not truth. Treat every answer like a pull request from an intern you must verify:

  1. Check claimed problems exist. If the AI says "this line has SQL injection", test it: try to inject ' OR 1=1 -- in your app and see what actually happens. Often the code is already safe and the AI is guessing.
  2. Apply one fix at a time. Change one thing, reload, verify, then continue. Big pasted rewrites hide regressions and teach you nothing.
  3. Keep behaviour tests. After each fix, repeat the "Check it works" steps from earlier lessons. A "fix" that breaks create/read/update/delete is worse than the bug.
  4. Ask for the why. If you do not understand a suggested change, ask the AI to explain it in beginner terms. Copy that explanation into your notes.
  5. Beware of invented APIs. If the AI suggests a function you never saw in this course, check the PHP manual (php.net) before using it — AIs sometimes invent plausible-sounding functions that do not exist.

Check it works

  1. Prompt A against public/app/handlers.php: the AI confirms every query uses prepared statements and every echo is escaped (or it names a real line to fix).
  2. Prompt B against public/app/index.php: labels, headings and focus styles are confirmed or fixed.
  3. Prompt C against the stylesheet: for each claimed break, open the real browser at that width (dev tools → device toolbar) and see it with your own eyes before changing code.
  4. Re-run lesson 6's "Check it works" list after each fix: the CRUD flow must keep working end to end.

Ask your AI

I am a beginner who just finished a course project. I want to use
you to test and review it (Lesson 13).

Please:
1. Suggest THREE more review prompts, in the same style as
   security / accessibility / responsive, that would catch other
   common beginner mistakes (for example: error messages leaking
   file paths, missing input trimming, broken links).
2. For each prompt, tell me exactly which file of my project I
   should paste.

My project files: public/app/index.php, public/app/handlers.php,
public/assets/css/style.css, public/assets/js/main.js.
