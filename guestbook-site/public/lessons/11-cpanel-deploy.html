Lesson 11 — deploy the CRUD app to cPanel

What you'll learn

  • How cPanel shared hosting is laid out on the server.
  • Where each project folder belongs.
  • How to check PHP 8.x and the PDO SQLite driver.
  • Folder permissions and a troubleshooting table for the classics.

Glimpse

The target layout on the hosting account (File Manager view): 

home/your-username/          (the account's home folder — NOT visible to visitors)
  src/
    config.php               <-- PHP can read this; browsers cannot
  data/
    .htaccess                <-- "Require all denied"
    guestbook.sqlite         <-- created on first run
  public_html/               (this IS the web root: your "public" folder)
    index.php
    lessons/
    app/
      index.php
      handlers.php
    assets/
      css/style.css
      js/main.js

The relative includes keep working: public/app/index.php asks for ../../src/config.php, which lands in the home folder's src/. No code changes needed when uploading.

Steps

  1. Zip the project. On your computer, zip the guestbook-site folder (right-click → Send to → Compressed folder on Windows).
  2. Log in to cPanel and open File Manager.
  3. Upload and extract. Upload the zip into your home folder, right-click it → Extract.
  4. Move public's CONTENTS into public_html. Your hosting's web root is public_html. Move everything from guestbook-site/public/ INTO public_html/ (index.php, lessons/, app/, assets/).
  5. Move src/ and data/ one level above public_html. Drag the whole src and data folders from guestbook-site/ into your home folder, so they sit NEXT TO public_html.
  6. Check the PHP version. In cPanel open MultiPHP Manager, select your domain, and set PHP to a version 8.x. (This project needs 8.x.)
  7. Check the SQLite driver. Open Select PHP Version → Extensions (or your host's PHP settings) and confirm pdo_sqlite and sqlite3 are enabled. On most hosts they are on by default.
  8. Set data/ permissions. In File Manager, right-click data → Permissions. PHP must be able to write the database file there. Usually 755 is enough; if you get "unable to open database file" errors, try 775.
  9. Open your site. Visit https://your-domain.com/ for the lessons and https://your-domain.com/app/index.php for the guestbook. Post a message!

Troubleshooting

Symptom Likely cause Fix
500 Internal Server Error PHP crashed. Common causes: PHP version below 8.x, a syntax error, or a bad .htaccess rule. Check error_log in your home folder (File Manager) for the real reason. Confirm 8.x in MultiPHP Manager. Remove or fix any custom .htaccess you added.
“unable to open database file” Wrong path or data/ is not writable by PHP. Check that src/ and data/ are siblings of public_html (see the tree above). Set data/ permissions to 755, or 775 if needed.
Blank page PHP is failing but display_errors is off in production. Look in error_log. While debugging you can temporarily enable display errors in Select PHP Version → Options; switch it back off afterwards.
HTMX not loading (post does nothing) The CDN script was blocked or the URL is wrong. Open dev tools → Console/Network. Confirm unpkg.com/htmx.org@1.9.12 returns 200. If your school/office network blocks CDNs, download htmx.js and load it from assets/js/ instead.

Check it works

  1. The lesson index opens at https://your-domain.com/.
  2. Posting in the guestbook works; the message survives a reload (it is in guestbook.sqlite on the server now).
  3. Open https://your-domain.com/data/guestbook.sqlite in the browser: you get a forbidden page, not a download. The .htaccess is working.
  4. Open https://your-domain.com/src/config.php: also forbidden/nothing — PHP files outside public_html cannot be reached by URL at all.
